# Duffing `duffrom2` MATLAB/Python parity and discrepancy diagnosis

Date: 2026-08-28  
Status: reproduced end to end as a read-only compatibility experiment. The authoritative retained MATLAB ROM name is `duffrom2`; the stale `rom2` interpretation is explicitly discarded.

## Bottom line

The MATLAB data path is now reproduced exactly enough to separate data errors from algorithmic and legacy-code differences.

- The 30 free trajectories saved in `regresslam.mat` are bit-for-bit identical to the trajectories generated by the external wrapper through `dynbatch.compute("hard")`.
- The 30 discrete-time eigenvalues saved in `regresslam.mat` are bit-for-bit identical to the exact-suite wrapper's optimized `duffrom2` spectrum.
- The controlled states, control histories, and time arrays decoded by DynSysLab's reusable tagged-CSV importer are bit-for-bit identical to the arrays reconstructed by the MATLAB wrapper.
- The wrapper's `B1`, `B2`, and constant `bb` arrays are bit-for-bit identical to the corresponding arrays saved in `regressB.mat`.
- Given the saved `duffrom2` spectrum and exact exported SINDy domain points, DynSysLab reproduces MATLAB's 30 polynomial eigenfunctions to relative error `2.39e-15` after one unit-magnitude complex phase per eigenfunction. Their zero/nonzero coefficient patterns are identical.
- After explicitly enabling the two legacy MATLAB conventions described below, Python reproduces `bb`, `B2`, and `B1` to relative errors `5.36e-15`, `8.20e-14`, and `1.56e-13`, respectively.

The former discrepancy was not caused by the wrong free data, CSV ordering, SINDy polynomial library, spectrum conversion, or regression algebra. It arose because the first wrapper used a hand-expanded RK4 loop. Its free trajectories differed from the suite by only `9.33e-15` at worst, but the legacy eigenvalue optimizer is so ill conditioned that this microscopic perturbation selected a radically different local result. Replacing that loop with the suite's exact hard-compute path made both `TS` and all 30 saved discrete eigenvalues exactly equal.

## Exact data pathway

### Free training data

- System: dimensionless double-well Duffing oscillator.
- MATLAB parameters: `alpha=4`, `beta=-1`, and the field named `gamma=0.5` (used in the equation as damping `delta`).
- Canonical DynSysLab form: `xdot=v`, `vdot=-0.5 v + x - 4 x^3 + u`.
- Input gain for this cleanup-suite path: one.
- Initial conditions: the first 30 columns of `DuffingICs.csv`, retained without rounding.
- Time: `0:0.01:8`, 801 samples per trajectory.
- Ensemble layout in `regresslam.TS`: trajectory-major rows `[x_1; v_1; x_2; v_2; ...; x_30; v_30]`, shape `60 x 801`.
- Exact wrapper layout: `2 x 801 x 30`; conversion to the saved row layout is exact.

### Controlled data

- Source: `noisyDuffData.csv`.
- Grammar: tagged `dynbatch`, `dynsys`, `dynclst`, `inst`, `time`, `sol`, `ctrl`, and `u` records.
- Decoded systems/trajectories: 100/100.
- Per trajectory: 201 state samples and 201 sample-aligned control values.
- The leading control value is the legacy zero initializer. This specific MATLAB regression uses all 201 sample-aligned values; transition-oriented DynSysLab APIs separately expose samples `2:end` when that is the intended model.
- CSV states, controls, and time match the wrapper exactly, with zero numerical difference.

## Eigenvalue optimization

The cleanup suite first runs standard two-state DMD, obtains a conjugate pair near

```text
0.998138273085493 ± 0.006731588871731 i
```

and constructs the degree-zero-through-four multiplicative lattice. There are 15 initial values. The optimizer fits one independent 15-value group to `x` and one to `xdot`, producing the 30-value pre-duality `duffrom2` spectrum.

The legacy MATLAB optimizer:

- calls constrained `fmincon` with real and imaginary parts bounded to `[-1.05, 1.05]`;
- analytically eliminates trajectory boundary coefficients through `inv(L'*L)*L'*h`;
- differentiates that normal-equation objective explicitly;
- repeatedly reports matrices that are close to singular or badly scaled, with observed reciprocal condition estimates as small as approximately `1e-266`.

This explains the extreme sensitivity. The former hand-RK4 wrapper differed from exact suite integration by only `2.46e-15` in relative Frobenius norm, yet its optimally assigned spectrum differed from the saved one by approximately `0.228` relative norm. With suite-hard integration, both the training array and optimized spectrum are bit-for-bit identical to the user's saved results.

DynSysLab's separated optimizer deliberately uses a more stable variable-projection calculation:

- `numpy.linalg.lstsq` with an explicit cutoff rather than inverse normal equations;
- bounded L-BFGS-B rather than `fmincon`'s interior-point path;
- the same exact `TS`, two initial 15-value groups, and no forced conjugate-pair postprocessing for this comparison.

It converged in about 3.0 seconds. Its trajectory residuals were `3.09e-4` for `x` and `2.16e-3` for `xdot`. It did not reproduce the MATLAB local spectrum:

| Spectrum comparison | Value |
|---|---:|
| Direct relative difference | 0.34949 |
| Optimal-assignment relative difference | 0.34356 |
| Mean assigned absolute difference | 0.09117 |
| Maximum assigned absolute difference | 1.71689 |
| Values outside the unit circle, MATLAB / Python | 1 / 3 |

This is now correctly classified as an optimizer-method difference, not a data mismatch. The supplied-spectrum boundary remains the clean experimental isolation point: either optimizer's discrete spectrum can be passed into the same SINDy stage.

## SINDy parity

The exact compatibility configuration is explicit and opt-in:

- eigenvalues supplied as discrete-time values and converted by `lambda=log(mu)/0.01` before solving the generator PDE;
- exact 270 exported MATLAB domain points, retained rather than regenerated from inferred bounds;
- all nonconstant monomials in `(x,v)` through total degree four, 14 features in MATLAB order;
- no centering, scaling, or dictionary normalization;
- analytic polynomial dictionary derivatives;
- one SVD of `Gamma-lambda*Theta` per eigenvalue;
- one absolute `1e-6` coefficient threshold, with no iterative threshold/refit;
- no conjugate-fit reuse.

On the supplied saved spectrum, Python took about 0.044 seconds. Each eigenfunction is mathematically defined only up to a nonzero complex scale. The inferred MATLAB/Python scales all had magnitude one to floating-point precision (`0.9999999999999987` to `1.0000000000000007`). After applying them, coefficient relative error was `2.39e-15`, maximum coefficient error was `4.73e-15`, and the sparsity patterns were identical.

This proves that the downstream SINDy expressions are no longer discrepant when the same spectrum, domain samples, generator convention, and sparsification policy are used.

## Observable reconstruction `C`

The MATLAB wrapper computes the full-state projection

```text
C = X * pinv(Z)
```

on all 24,030 free state samples. The Python compatibility reconstruction differs by only `8.75e-14` relative norm (`1.31e-12` maximum entrywise difference). MATLAB's reported state reconstruction RMSE is approximately `1.97e-15` for `x` and `4.14e-15` for `v`.

The compatibility `C` is retained separately from DynSysLab's canonical observable-reconstruction object because the legacy lifted-state evaluation is conjugated. A `C` matrix is coordinate-dependent: changing eigenfunction phase or conjugation requires the corresponding inverse change in `C`.

## The two legacy MATLAB inconsistencies

These are reproduced only in the candidate compatibility branch.

### 1. Controlled derivative dynamics use different parameters

The free training system is explicitly changed to cubic coefficient four. The tagged CSV does not serialize Duffing physical parameters, so the legacy loader creates each controlled system with Duffing defaults. `KROM.get_B_parts` evaluates derivatives through the last loaded controlled system. Consequently:

- free training and SINDy domain: `vdot=-0.5v+x-4x^3`;
- controlled derivative regression: `vdot=-0.5v+x-x^3+u`.

The controlled state trajectories themselves remain the saved source data; the mismatch enters when MATLAB recomputes `DX` for regression.

### 2. Lifted values and lifted derivatives use different conjugation

The polynomial state path evaluates `[Theta*psi]'`, where MATLAB apostrophe is a conjugate transpose. Thus the stored lifted values use `conj(Theta*psi)`. The derivative path uses nonconjugating `transpose(psi)*Gamma`. Therefore `Z` is conjugated while `DZ` is not.

DynSysLab's canonical branch uses one consistent analytic eigenfunction for value and gradient evaluation. The legacy behavior is available only by explicitly assembling aligned arrays and invoking the candidate statistical regression.

## Control-matrix regression

The exact array-level regression is now tooled as the opt-in candidate function `fit_aligned_lifted_residual_control_candidate`. It accepts aligned complex `Psi`, `dPsi/dt`, physical/model inputs, and continuous generator `A`; it infers no dynamics, derivative, conjugation, or coordinate convention. This makes the statistical step applicable to any KROM that can supply those arrays.

For `duffrom2`, the MATLAB and Python compatibility matrices agree:

| Matrix | Shape | Saved `regressB` vs wrapper | Python compatibility vs wrapper |
|---|---:|---:|---:|
| Constant `bb` | `30 x 1` | exact | `5.36e-15` relative |
| Bilinear offset `B2` | `30 x 1` | exact | `8.20e-14` relative |
| Bilinear operator `B1` | `30 x 30` | exact | `1.56e-13` relative |

The matrix values themselves are retained at full precision in `matlab_playground_duffing_lambdaopt_sindy_regression_suite_hard.matrices.txt` and the parity NPZ artifact.

The regressions are poor approximations of the lifted control residual despite this exact implementation parity:

| Branch | Constant residual | Bilinear residual | `||B1||_F` |
|---|---:|---:|---:|
| Legacy `duffrom2` conventions | 0.999921 | 0.998524 | 534.85 |
| Correct dynamics only | 0.999923 | 0.998537 | 527.21 |
| Correct eigenfunction evaluation only | 0.999937 | 0.998742 | 489.28 |
| Fully canonical, MATLAB supplied spectrum | 0.999939 | 0.998752 | 481.08 |
| Fully canonical, Python optimized spectrum | 0.994209 | 0.519392 | 68.60 |

The first four direct matrix norms are coordinate-dependent and should not be interpreted as physical invariants. The residual comparison is the useful diagnostic. Correcting either legacy inconsistency does not rescue the regressed approximation for the MATLAB spectrum. The Python optimizer's different spectrum happens to yield a substantially better bilinear regression on these data, but a residual near `0.52` is still too large to justify promotion to the default controller.

Most importantly, these poor regression residuals do not contradict successful Duffing KLQR with the exact state-dependent map `B_psi = nabla(Psi) B`. The exact map and the statistical constant/bilinear approximations are different controller-input representations and must remain separately selectable.

## Code-boundary decisions

- MATLAB remains a read-only evidence source. The wrapper is external and hashes source/input files before and after execution.
- `domain_points` is an explicit SINDy input mode, so an external nonuniform mesh can be retained as data rather than reconstructed heuristically.
- `dictionary-gradient` and `matlab-single-absolute` are opt-in SINDy policies. Existing iterative/normalized defaults are unchanged.
- The aligned lifted-residual regression lives in `rom.candidates`; it is not re-exported by the standard `rom` package and cannot silently replace exact `B_psi`.
- The normal Python optimizer remains numerically stabilized. It is not changed to reproduce MATLAB's inverse-normal-equation instability.
- The legacy parameter and conjugation bugs are documented compatibility switches in the experiment runner, not system defaults.

## Recommended next experiments

1. Keep the supplied-spectrum SINDy route as the primary isolation boundary when testing controller behavior. It is now verified to reproduce the MATLAB eigenfunctions.
2. Compare exact `B_psi` KLQR for the MATLAB and Python-optimized spectra before comparing approximate `B` models. This isolates eigenfunction/control geometry from regression error.
3. Treat the legacy optimizer result as a reproducible experimental artifact, not as a stable numerical estimator. If its particular spectrum is desired, retain and load it rather than expecting a stabilized optimizer to rediscover it.
4. Evaluate constant and bilinear maps with phase-space error fields and closed-loop tests separately. Global regression residual alone does not identify where an approximation fails.
5. Do not copy the CSV parameter-loss or mixed-conjugation behaviors into production. They are now understood well enough to emulate diagnostically without normalizing them into the architecture.
