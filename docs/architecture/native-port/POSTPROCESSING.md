# Capability ledger: `postprocessing/`, `spectral/`, `analysis_data/` vs the native core

Scope: every Python file under `postprocessing/` (koopman, pca_pod, lcs, ssm, method_handlers, cli, processor, planning, policies, resampling, resources, workflow, formal_report, linalg_backends), `spectral/`, `analysis_data/`. All paths are relative to the repository root.

Native dispatch reference: `workflow/native/src/Postprocess.cpp:executePostprocess`. The per-source branch accepts `hankel_matrix, koopman_spectral/resdmd/..., dmd, hdmd|hankel_dmd, sindy, control_regression, koopman_validation, boundary_eigenfunctions, eigenvalue_optimization, edmd, havok, hankel_pod|hankel_svd, svd, pca, pod, bagged_pca, robust_pca` plus `eigenfunction_errors, eigenfunction_expansion, domain_field, coordinate_transform, ...`. `pooledMethod()` lists only the history/control stages, so `hdmd` and `sindy` run once per source. `precedingSpectrum` chains `dmd/hdmd/eigenvalue_optimization` into `sindy/boundary_eigenfunctions`.
