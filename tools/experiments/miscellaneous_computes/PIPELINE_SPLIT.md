# Proposed pipeline split

This is a design recommendation. All new implementations, entry points and skills are in the standalone miscellaneous computes side-car. The production system already has interfaces for several of these operations, so promotion should extend those interfaces. [Existing dependency boundaries](../../../docs/architecture/PIPELINE_BOUNDARY_REFACTOR_2026-10-31.md) · [Native target definitions](../../../native/CMakeLists.txt)

## Assign ownership by operation

| Capability | Proposed owner | Boundary to preserve |
|---|---|---|
| Frozen observation transforms | Extend `dynsyslab_observation` and the coordinate archive through [HistoryObservation.hpp](../../../native/include/dynsyslab/core/HistoryObservation.hpp), [HistoryObservationArchive.hpp](../../../native/include/dynsyslab/core/HistoryObservationArchive.hpp) and [CoordinateTransform.hpp](../../../native/include/dynsyslab/core/CoordinateTransform.hpp). | Apply signed encoders, lag layouts, causal taps, channel scales and existing window integrals. A stream owns its own history buffer. Preserve the existing oldest-first scalar archive convention and record any permutation into a newest-first multichannel layout. |
| Basis fitting and discrete spectral analysis | Extend the training-side pooled history operation in [HistoryKoopman.hpp](../../../native/include/dynsyslab/core/HistoryKoopman.hpp). Share Gram/SVD primitives through `dynsyslab_numerics` or `dynsyslab_decomposition`. Keep a within-record DMD shift fit in `dynsyslab_spectral`. | A fitted chart can feed continuous SINDy, discrete DMD, or a supervised readout. Save the sample interval, lag units, signs, normalization, rank and training source IDs. Downstream deployment only uses that frozen chart. |
| Continuous vector-field identification | Extend `dynsyslab_identification` through [SindyDynamics.hpp](../../../native/include/dynsyslab/core/SindyDynamics.hpp) and the [existing identification workflow](../../../workflow/native/src/SindyDynamicsPostprocess.cpp). Share generic linear algebra through the existing numerics layer. | Fit each SINDy row, including weights, physical weak windows and constraints. Persist field space, support, library scaling, and whether rows are learned, imposed, or inherited. A frozen RHS evaluator should have no fitting dependency. A general nonlinear SINDy RHS has its own continuous-model semantics. |
| Autonomous propagation | Extend the solver/foundation [Integrator API](../../../native/include/dynsyslab/core/Integrator.hpp) with common partial-result status, guards and arbitrary output clocks. Reuse matrix exponential facilities in numerics for affine systems. | The integrator takes a declared field and initial state. Fit selection, waveform calibration and held-out comparison belong to callers. Keep clock conversion and continuous/discrete model identity explicit. |
| Physical measurements and supervised inverses | Keep emission physics, range and direction in the physical model's [AcousticReceiver](../../../native/include/dynsyslab/core/AcousticReceiver.hpp). Use observation for generic channel alignment. Put offline readout fitting under [Reconstruction](../../../native/include/dynsyslab/core/Reconstruction.hpp), with a frozen map consumable by estimation. | Preserve source/arrival-time conventions and physical correction terms. The estimator at a query time needs measurements and a saved inverse. Archive the training labels, neighbor metric/scales and optional neighbor provenance with the fitted map. |
| Crossings and global closure | Put dense-path intersection/refinement in [PhaseSpace](../../../native/include/dynsyslab/core/PhaseSpace.hpp). Keep coordinate fiber tests and proof certificates at [CoordinateClosure](../../../native/include/dynsyslab/core/CoordinateClosure.hpp) and [GlobalJetClosure](../../../native/include/dynsyslab/core/GlobalJetClosure.hpp). | Geometry returns visit brackets, vectors and refinement residuals. A certificate requires explicit equations, assumptions, domain and an applicable proof procedure. The [existing CLI](../../../workflow/native/src/CoordinateClosureQuery.cpp) can report an unresolved order. |
| Validation, archives and workflow | Put numerical comparison of supplied series, ring/peak errors, kinematic checks and delay consistency in postprocessing/validation. Have neutral workflow own record splits, validation-only selection, and experiment composition. Archiver owns immutable model/curve references and schema versions. | Persist derivative-label provenance, training/validation/test IDs, prehistory, units, time coverage and failed candidates. A partial forecast must retain the full requested reference. The selection driver consumes validation metrics. |
| Viewer | Extend the existing [native Viewer services and CLI](../../../viewer/native/CMakeLists.txt) for styles, combined reference/baseline/model pages, per-curve clocks and bounded display simplification. | Render through the existing Viewer API. Full-resolution scientific data and fitting stay in their owning modules. Only display vertices are thinned. |

The operational distinction in the four-mode RPE result illustrates two boundaries at once. Observation owns the invertible delay chart and its derivative pushforward. Identification owns the fitted accelerations and their prior. Either part can be reused or changed independently, and replay needs only their frozen definitions. [Experiment provenance](TOOLKIT_REVIEW.md#reading-the-four-coordinate-rpe-plot)

## Suggested order of promotion

1. **Start with frozen coordinates and result comparison.** Standardize tap layout, units, source scale, modeled-versus-measured derivatives and initial history in the existing archive contract. Promote time/sample coverage, full-reference handling, per-channel errors, peak matching and decoded-rate checks. Acceptance should include scalar archive round trips, fractional and irregular lags, train/hold-out sign parity and an early-stopping model shown against the complete reference.
2. **Then promote direct SINDy fitting and replay.** Add the widely applicable weighted and weak fits to native identification, and portable, fitting-free evaluation to its runtime contract. Use the standalone implementations as independent oracles. Check agreement of supports, coefficients, saved equations and free trajectories on the four direct RPE fits and a non-RPE analytic fixture. Exercise guard termination and compare an affine exact propagator with an independent RK solver.
3. **Promote sensor readouts and empirical closure diagnostics independently.** The sensor path can use the existing receiver recording and state-estimation contracts. The crossing path can use phase-space geometry and the existing closure CLI. Check one receiver versus a delayed copy on common clocks, a case with a genuinely different channel, a known transverse crossing and a projected crossing that separates in a lifted state.
4. **Keep experimental model families in the side-car for now.** Local tangent stabilization, pair networks, inherited endpoint laws, tuned damped interiors, oscillator locking, waveform shooting and pressure-specific dictionaries make scientific assumptions that differ by system. Keep their training scripts and legacy schema adapters here until a second application demonstrates a stable public contract. Extract a native implementation and independent tests before exposing any of them as a pipeline job.

A native public API and compiled CLI, an archive round trip, regression coverage on analytic data and the relevant archived experiment, and a working consumer would be the promotion criteria. Numerical Python experiments remain available here as reference implementations. The study skills can move alongside the corresponding public workflows when those interfaces exist.
